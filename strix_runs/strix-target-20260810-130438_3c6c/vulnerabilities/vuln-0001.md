# Unauthenticated disclosure of unpublished sites in GET /api/map-sites

**ID:** vuln-0001
**Severity:** MEDIUM
**Found:** 2026-08-10 19:45:03 UTC
**Target:** Cluster Web Builder (Next.js app) /api/map-sites
**Endpoint:** /api/map-sites
**Method:** GET
**CWE:** CWE-200
**CVSS:** 5.3
**Fix Effort:** Trivial

## Description

The public, unauthenticated `GET /api/map-sites` endpoint returns the business name, internal site ID, and location of every site that has a non-null `location` field, including sites that are still in private `DRAFT` or `GENERATED` status and have never been published. This exposes private business metadata of users who have not chosen to make their site public.

## Evidence

The route query filters only on `location` and never on publish status:

```ts
const sites = await prisma.site.findMany({
  where: { location: { not: null } },
  select: { id: true, businessName: true, location: true, createdAt: true },
  orderBy: { createdAt: "desc" },
  take: 60,
});
```

The `Site` schema shows `status SiteStatus @default(DRAFT)`, with `DRAFT` as the default and `PUBLISHED` set only on explicit publish, so unpublished sites are included by this query.

A search over the handler for any authentication or ownership control (`getUserBySessionToken`, `SESSION_COOKIE`, role, `userId`) returns no matches — the endpoint is fully anonymous:

## Impact

Unauthenticated attackers can enumerate the private business metadata (business name and operating location) of every site in the system, including unpublished `DRAFT` and `GENERATED` projects. This discloses information users have not opted to make public and can be used to build targeted reconnaissance, or to identify and infer the existence of in-progress businesses before they launch.

## Technical Analysis

The route handler in `app/api/map-sites/route.ts` performs a Prisma query with only one filter:

```ts
const sites = await prisma.site.findMany({
  where: { location: { not: null } },
  select: { id: true, businessName: true, location: true, createdAt: true },
  orderBy: { createdAt: "desc" },
  take: 60,
});
```

The `where` clause filters solely on `location: { not: null }`. It does **not** filter on `status`, so the query returns sites in all states: `DRAFT`, `GENERATED`, and `PUBLISHED`. In the Prisma schema, `Site.status` defaults to `DRAFT` and is only set to `PUBLISHED` when a user explicitly publishes (see `app/api/sites/[siteId]/publish/route.ts`). Every generated site with a non-null `location` therefore appears, including private drafts.

The handler also performs **no authentication or authorization** whatsoever. A search for auth helpers (`getUserBySessionToken`, `SESSION_COOKIE`, role checks, `userId` filters) at the top of the file returns nothing. The only protection is a per-IP rate limit (`consumeRateLimit("map-sites", ip, 60, ...)`), which limits volume but does not gate who can call it or what data it returns.

This means an anonymous caller can enumerate the business name, geographic location, internal site ID, and creation time of any user's private, unpublished project. The `businessName` is user-supplied and often the business's real name; `location` is where the business operates. Both are metadata the user has not opted to disclose (unlike `PUBLISHED` sites, which are intentionally public at `/s/{slug}`).

## Proof of Concept

1. Send an unauthenticated `GET` request to `/api/map-sites`.
2. Inspect the JSON response.
3. Create a test site (either as a logged-in user or as a guest) with a `location` value that resolves to a known coordinate, but leave it unpublished (`status = DRAFT`).
4. Send the `GET /api/map-sites` request again without any session cookie.
5. Observe that the unpublished site's `businessName`, `id`, `location`, and `createdAt` are present in the anonymous response alongside published sites, confirming unauthorized disclosure of a private draft.

````python
```python
import requests

# Unauthenticated request with no session cookie
url = "http://localhost:3000/api/map-sites"
r = requests.get(url, timeout=15)
print("status:", r.status_code)

if r.status_code == 200:
    markers = r.json()
    print("total markers returned:", len(markers))
    # Every marker leaks businessName + location for sites regardless of publish status.
    for m in markers[:5]:
        print(m)
else:
    print("unexpected response:", r.text)
```
The endpoint returns one object per site with `label` (business name), `location`, `id`, and `createdAt`. Because the route never filters by `status` nor requires a session, unpublished drafts appear in this public listing.
````

## Remediation

Restrict the map listing to publicly published sites only. Add a `status: "PUBLISHED"` filter to the Prisma `where` clause so that `DRAFT` and `GENERATED` (unpublished) sites are excluded, mirroring the public-site access rules already used by the `/s/{slug}`, `/d/{domain}`, and `/api/public/sites/{slug}/...` routes. Optionally also require that the returned `PUBLISHED` sites belong to a user with an active plan when publishing is gated on it, and consider whether `businessName`/`location` should be considered public metadata at all for a map feature. Apply the same status gate consistently on any future aggregation endpoint.

## Assumptions

Assumes one or more sites exist with a non-null `location` and a status other than `PUBLISHED` (the default `DRAFT`, or `GENERATED`). Sites created through the normal onboarding flow can carry a `location`; the endpoint returns them regardless of whether the owner has published.
